# Employee Ownership Journey v0.2

## Optimized Guided Journey

## 1. Design Objective

The journey should accomplish four things:

1. Understand what the owner wants.
2. Identify what is flexible versus nonnegotiable.
3. Explore potential ownership and financing paths.
4. Produce a Professional Review Package.

The user should not need to understand ESOPs, seller financing, valuation, tax structures, or M&A terminology to begin.

The journey should progressively reveal complexity only when it becomes relevant.

---

# 2. THE JOURNEY'S CORE LOGIC

The optimized journey follows:

**Goal → Priorities → Constraints → Preferences → Business Context → Scenarios → Professional Review**

Not:

**Transaction Type → Forms → Documents → Professionals**

The owner starts with **what they want**, not with a financial structure.

**Create income over time**

* Transition quickly

* Preserve company culture
* Keep the company independent
* Give employees meaningful ownership
* Generate future income

# 6. STAGE 3: PRIORITIZE

Only if the owner selected multiple secondary objectives:

### Put your priorities in order.

Rank the selected items.

**Primary Objective**

**Secondary Priorities**

**Tertiary Priorities**

No ranking of irrelevant choices.

# 7. STAGE 4: NONNEGOTIABLES

This should happen immediately after priorities are established.

For each selected objective or important preference:

### How important is this?

**☐ This is nonnegotiable**

> This means it is a must-have for you to move forward.

If not selected, the item remains a preference.

The system therefore distinguishes:

**Nonnegotiable**

**Strong Preference**

**Preference**

# 8. STAGE 5: WHAT DO YOU WANT TO AVOID?

### Are there outcomes you want to avoid?

**Select any that apply**

* Losing employee ownership
* Selling to an outside buyer
* Remaining involved long-term
* Taking on excessive debt
* Waiting many years for proceeds
* Disrupting employees
* Moving the company
* Losing control too quickly
* Taking on unfamiliar partners
* Other

Optional:

**Nothing specific**

This creates **negative constraints**.

The platform now knows not only:

**What the owner wants**

but also:

**What the owner does not want.**

# 15. STAGE 12: LIQUIDITY PREFERENCE

**Direct Employee Purchase**

**Management Buyout**

**Staged Employee Ownership**

# 18. STAGE 15: SCENARIO BUILDER

For each relevant scenario:

## Scenario

**What it is**

Plain-language explanation.

### Why it appeared

> You told us employee ownership is very important and you want substantial cash at closing.

### Current assumptions

* Approximate business value
* Revenue
* EBITDA/cash flow
* Debt
* Desired liquidity
* Timing
* Owner involvement

### Potential characteristics

What the structure might accomplish.

### Trade-offs

What could become more difficult.

### Must-have check

**Does this appear compatible with your nonnegotiables?**

### Questions for your professionals

What needs to be validated.

The platform should not call this a recommendation.

---

# 19. STAGE 16: WHAT-IF EXPLORATION

Give the user a small number of controlled adjustments.

For example:

### What if you received less cash at closing?

**Explore**

### What if you stayed involved for 18 months instead of 6?

**Explore**

### What if you kept more of the seller note?

**Explore**

The user can compare the effect without losing the original scenario.

---

# 20. STAGE 17: SCENARIO COMPATIBILITY

Every scenario receives a simple compatibility assessment against the owner's own requirements.

For example:

### Scenario A

**Employee Ownership + Seller Financing**

**Nonnegotiables**

✓ Employee ownership

✓ Transition within 18 months

**Potential conflict**

⚠ Current assumptions may not support desired cash at closing.

### Scenario B

**ESOP**

✓ Employee ownership

⚠ Requires specialized professional review

⚠ Additional structure and transaction requirements may apply

This is a **constraint analysis**, not a ranking.

# 27. WHAT WE REMOVED OR CHANGED

The original journey contained some redundancy.

### Removed duplication

Instead of:

**"What matters most?"**

then later:

**"How important is employee ownership?"**

we use the earlier answers to determine whether the second question is necessary.

### Delayed complexity

Instead of asking about seller financing early:

**Goal → Liquidity preference → Seller financing only if relevant**

### Reduced unnecessary ranking

**Select up to 3 → Rank those 3**

rather than ranking a large list.

### Added negative constraints

**What do you want to avoid?**

### Added quantitative thresholds only when relevant

Don't ask:

> "How much cash do you want?"

until the user has indicated that cash is actually important.

### Added scenario what-if

Let the user test changes instead of forcing them to answer every possible question up front.

---

# 28. NEW JOURNEY BUILDER RULE

The Journey Builder should support a special property:

## "Ask Only When Relevant"

Each question can contain a rule such as:

```text
Show Question:
"What would you like to do with a seller note?"

ONLY IF:
seller_financing_interest = yes
```

Or:

```text
Show Question:
"How much would you like at closing?"

ONLY IF:
liquidity_priority = high
```

Or:

```text
Show Professional Role:
ESOP Specialist

ONLY IF:
scenario_contains_ESOP = true
```

This prevents questionnaire bloat.

---

# 29. ANOTHER NEW PROPERTY: INFORMATION VALUE

Each question should have an internal priority:

**Essential**

**Useful**

**Optional**

The engine should prefer:

> **Essential information first.**

If a question does not materially affect the next decision, it should be delayed.

This is how we keep the journey short.

---

# 30. ANOTHER NEW PROPERTY: QUESTION EXIT

Every exploratory section should have an exit.

For example:

> **We have enough information to create some initial scenarios.**

**Show Me My Options**

**Keep Exploring**

The platform should not force the owner to answer every available question before giving them value.

---

# 31. THE IDEAL FIRST SESSION

The first session should be capable of producing meaningful output without requiring a complete business data room.

An owner should be able to get to:

### Your Preliminary Ownership Plan

with approximate information.

Later, the owner can return and add:

* Exact financial information
* Documents
* Professional input
* Financing information
* Valuation
* Employee information

The journey grows with the transaction.

---

# 32. FINAL JOURNEY PRINCIPLE

The Journey Engine should follow:

> **Ask the smallest useful question.**
>
> **Show why it matters.**
>
> **Give the user 2–3 understandable choices.**
>
> **Allow uncertainty.**
>
> **Allow nonnegotiable requirements.**
>
> **Branch only when necessary.**
>
> **Show consequences.**
>
> **Let the user go back and explore.**
>
> **Create value before asking for more information.**
>
> **Never confuse a platform scenario with professional advice.**

The objective is not to collect the most information.

**The objective is to help the owner discover and articulate what they want, with the least cognitive burden possible.**
